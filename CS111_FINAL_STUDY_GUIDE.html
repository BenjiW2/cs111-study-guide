Virtualization

One thing looks like another: threads virtualize CPU, address spaces virtualize memory, files virtualize disks, VMs virtualize hardware.

Atomicity

Locks make critical sections indivisible. Logs make multi-block file-system updates recoverable.

Locality

Schedulers, TLBs, page replacement, file caches, disk scheduling, and FTL garbage collection all exploit locality.

Concurrency

Process vs thread

A process owns an address space and resources. A thread is a stream of execution inside a process.

  • Threads in one process share heap, globals, file descriptors, and page maps.
  • Each thread has its own registers, program counter, stack, and scheduling state.
  • Processes created by fork get separate memory after the fork.

Fork tracing

pid_t pid = fork();
if (pid == 0) {
    // child: fork returned 0
} else {
    // parent: pid is child's process id
}

After fork, both processes continue from the next instruction. Same code path, different return value, separate address spaces.

Final trap

A dispatcher is OS code that runs when needed. It is not a special high-priority thread. Preemption also does not release locks; only the owning thread can safely release them.

Synchronization

Monitor recipe

  1. Make all shared state private.
  2. Protect it with one mutex unless the problem clearly needs finer-grained locks.
  3. Write the wait condition as a Boolean predicate over shared state.
  4. Use while, not if, around condition-variable waits.
  5. Update shared state while holding the lock.
  6. Notify after the state change that might make another predicate true.

Condition variable meaning

A condition variable is not the condition. It is a sleeping/wakeup queue. The condition is your predicate, such as current_load + weight <= capacity.

std::unique_lock<std::mutex> lock(mutex_);
while (!can_proceed()) {
    cv_.wait(lock);
}

Common wrong answers

  • Using if instead of while.
  • Sleeping while still logically holding a resource.
  • Not counting both waiting and active threads.
  • Updating state after notify instead of before.
  • Partially reserving resources before all are available.

Scheduling

Thread states

  • New threads start ready.
  • Ready → running when dispatcher selects them.
  • Running → ready when time slice expires or preempted.
  • Running → blocked when waiting for I/O, lock, or CV.
  • Blocked → ready when the awaited event occurs.

4.4 BSD intuition

Recent CPU usage lowers priority. Mostly blocked/interactive threads get higher priority than compute-bound threads. A single brief block does not instantly erase a long history of CPU use.

Response time trap

Smaller time slices do not automatically improve average response time. If a task would have finished soon, interrupting it can make everyone wait longer.

Memory

Linker

Combines object files, resolves symbols, relocates references, lays out text/data/bss, and may align sections to page boundaries for protection.

Stack vs heap

Stack allocation is LIFO and has one contiguous free region. Heap allocation supports arbitrary lifetimes and creates fragmentation/leaks/dangling pointers.

Base/bound and segmentation

Base/bound gives one protected contiguous region. Segmentation gives multiple variable-sized protected regions but still has external fragmentation.

Allocation trap

If a question asks whether a 400-byte allocation can fit after freeing two 200-byte blocks, check whether those blocks are adjacent in memory. Total free space is not enough; contiguity matters.

Paging

Address translation checklist

  1. Find page size, so offset bits = log2(page_size).
  2. Split virtual address into virtual page number and offset.
  3. Use page-table entries to find physical page frame.
  4. Physical address = physical page frame bits + unchanged offset.
  5. For multilevel tables, split VPN bits into index chunks.

TLB

A TLB caches successful virtual-to-physical translations. Entries need the virtual page tag, physical page frame, permissions, and usually address-space identity/ASID if not flushed on every process switch.

Demand paging

Pages are loaded only when touched. A missing page causes a page fault. Replacement policies decide which resident page to evict.

PolicyIdeaExam point

Thrashing

If the paging disk is near 100% utilized and CPU is mostly idle, the system is thrashing. More CPU cores or scheduler changes usually do not fix it. Reduce the working set, add memory, or speed up paging I/O.

Storage

Disk mental model

Random I/O is slow because seek and rotation dominate. Sequential access is faster because adjacent blocks reduce mechanical movement.

Block size tradeoff

Larger blocks improve sequential throughput and increase max file size in indexed systems, but increase internal fragmentation and can waste cache space.

MechanismWhat to remember

File Systems

Inode

Metadata plus block pointers. It does not store the file's pathname.

Directory

A file mapping names to inode numbers. Pathname lookup repeatedly reads directory files.

Links

Hard link = another directory entry to same inode. Symbolic link = special file containing a path string.

Unix V6 large-file shape

A small file stores block numbers directly in the inode. A large file sets ILARG; inode addresses point to indirect blocks, with the last address able to point to a doubly indirect block.

if (inode.i_mode & ILARG) {
    // i_addr[0..6] are indirect block pointers
    // i_addr[7] can be a doubly-indirect block pointer
}

Name-location trap

Putting file names in inodes would make directory lookup slower: the OS would need to read many inodes instead of scanning many compact names in directory blocks.

WAL invariant

The log entry must reach disk before the home-location metadata update it describes. Log replay must be idempotent because recovery can crash and restart.

Flash

Why flash is weird

  • Reads are page-sized and fast.
  • Writes can clear bits from 1 to 0.
  • Setting bits back to 1 requires erasing a large erase unit.
  • Erase units wear out.

FTL

The Flash Translation Layer maps logical disk blocks to physical flash pages. Writes go to new pages, old pages become garbage, and garbage collection later erases whole units.

Write amplification

If an erase unit has utilization U, simplified write amplification is 1 / (1 - U). At U = .9, the device may do about 10 units of physical writing per unit of logical new data.

TRIM

The FTL does not know a deleted file's blocks are dead unless the OS tells it. TRIM reduces useless copying of deleted data during garbage collection.

Trust

Assumption

Weak trust: no strong evidence. "I just assume this source is okay."

Inference

Trust from evidence: tests, inspection, history, observed behavior, reputation with reasons.

Substitution

Trust because something else trusted backs it: signatures, vendors, institutions, recovery mechanisms.

Ethics answer template

Name the trustor, trustee, what was trusted, the evidence or missing evidence, the failure mode, and a concrete mitigation.

Technology traps

  • Engagement is not truth.
  • Authoritative AI tone is not accuracy.
  • Many copies of one false claim are not independent evidence.
  • Synthetic media makes both belief and dismissal easier to manipulate.

Virtual Machines

VM vs process

A process sees a user-level abstraction. A VM sees something that looks like hardware: privileged instructions, physical memory, MMU behavior, devices, traps, and interrupts.

Hypervisor

The hypervisor controls real hardware and provides virtual hardware to guest operating systems.

Trap-and-simulate

  1. Guest OS executes privileged instruction, such as CLI.
  2. CPU traps to the hypervisor.
  3. Hypervisor updates virtual CPU state as if the instruction executed.
  4. Guest resumes after the instruction.
AddressMeaning

Final Patterns

T/F conceptual

Rewrite the statement with one precise counterexample. Example: preemption does not release locks because only the owner knows the protected invariant is safe.

Synchronization design

Most points are in state variables and wait predicates. Code syntax matters, but the invariant matters more.

Address translation

Draw the bit split. Offsets are unchanged between virtual and physical addresses.

Filesystem coding

List every structure read/written: inode, directory block, indirect block, doubly indirect block, free map, data block.

Crash questions

Say exactly which disk writes happened before the crash. Vague "it might be inconsistent" answers are usually too weak.

Tradeoff questions

Separate performance, consistency, and durability. One change can improve one while worsening another.

Drill

Why does a condition-variable wait use while instead of if?
Answer

Waking only means the predicate may now be true. Another thread may run first and falsify it, or the wakeup may be broad/spurious. Re-check under the lock.

What are the four deadlock conditions?
Answer

Limited access/mutual exclusion, no preemption, multiple independent requests while holding resources, and circular wait.

Why do multilevel page tables save memory?
Answer

They allocate lower-level page-table pages only for used regions of the virtual address space, instead of requiring one giant contiguous table for every possible virtual page.

Does increasing page size help TLB misses?
Answer

Often yes, because each TLB entry covers more bytes. But it can increase internal fragmentation and may pull in more useless data.

Why can a hard link outlive deletion of the original pathname?
Answer

The file is the inode, not the name. A hard link is another directory entry pointing to the same inode, and the inode persists while its reference count is nonzero.

Why must WAL replay operations be idempotent?
Answer

Recovery itself can crash. If replay restarts, applying the same log entry again must leave the disk in the same correct state.

Why is flash garbage collection expensive at high utilization?
Answer

Most pages in a victim erase unit are still live, so the FTL must copy many live pages to free only a small amount of space. Write amplification grows as 1/(1-U).

What is trap-and-simulate?
Answer

The guest runs directly until it tries a privileged operation. That operation traps to the hypervisor, which simulates its effect on virtual machine state and resumes the guest.

How should an ethics/trust answer be structured?
Answer

Identify trustor, trustee, trusted claim/action, evidence type, failure mode such as over-trust or untrustworthiness, and a concrete verification or design improvement.
